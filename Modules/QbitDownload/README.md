# QbitDownload

Модуль для Lampac: кнопка **«Скачать»** в Lampa → загрузка торрента через **qBittorrent** на диск → раздел **«Загрузки»** с просмотром **оффлайн** (файл отдаётся напрямую с диска, без интернета/сидов).

## Как работает
1. Кнопка «Скачать» на карточке фильма ищет раздачи через JacRed (`/api/v1.0/torrents`) и шлёт выбранный magnet в `/qdl/add`.
2. `/qdl/add` логинится в qBittorrent (WebUI API) и добавляет торрент в категорию `lampa`, сохраняя в общую папку `downloadsPath`.
3. qBittorrent качает полный файл на диск (общий том с Lampac).
4. Раздел «Загрузки» (`/qdl/list`) показывает прогресс; воспроизведение идёт через `/qdl/stream` — файл отдаётся с диска с поддержкой Range (перемотка), играет оффлайн.

## Эндпоинты
| Маршрут | Назначение |
|---|---|
| `GET /qdl.js` | клиентский плагин Lampa (кнопка + раздел «Загрузки») |
| `GET /qdl/search?query=&year=` | поиск раздач через JacRed (нормализованный JSON) |
| `GET|POST /qdl/add?magnet=\|parselink=&title=` | добавить в qBittorrent (резолвит parselink → magnet) |
| `GET /qdl/list` | список загрузок (категория `lampa`) с прогрессом. **Сезоны одного сериала отдаются ОДНОЙ карточкой** (`SeriesMerge.cs`, qdl 2.78): группа — один TMDB id + `media_type=tv` (jut.su/XSMART не участвуют), в карточке `parts[]` и `seasons[]`; киллсвитч `mergeSeasons` |
| `GET /qdl/files?hash=` | файлы торрента |
| `GET /qdl/episodes?hash=` | объединённый плейлист сериала: серии основной раздачи + доноров охоты, а у склеенной карточки — **всех раздач группы** (сезон за сезоном, дедуп по `epkey`). У каждой серии свой `hash` |
| `GET /qdl/stream?hash=&index=` | отдать файл с диска (Range/seek, оффлайн) |
| `GET /qdl/delete?hash=&deleteFiles=` | удалить загрузку |
| `GET /qdl/season/watch?hash=[&from=]` | **«жду следующий сезон»** (`SeasonWatch.cs`, qdl 2.79): подписка на СЕРИАЛ по TMDB id, а не на раздачу. `from` — с какого сезона ждать (по умолчанию следующий за самым старшим скачанным) |
| `GET /qdl/season/watch/remove?hash=\|id=` | снять маркер (с диска не удаляется ничего — контур умеет только добавлять) |
| `GET /qdl/season/watch/list` | дамп `/qdl-data/season-watch.json` |
| `GET /qdl/season/watch/check[?dry=1][&id=]` | ручной прогон тика; `dry=1` — отчёт «что бы сделал» без единой записи |
| `GET /qdl/live/cameras?date=` | **D1VERSY LIVE**: камеры, у которых ЕСТЬ записи за локальный день (+ сколько камер всего) |
| `GET /qdl/live/recordings?camera=&date=` | записи одной камеры за день (время локальное, длительность, размер) |
| `GET /qdl/live/days[?back=]` | дни, за которые записи вообще есть (для выбора даты) |
| `GET /qdl/live/watch` | **D1versy Live (эфир)**: все камеры + кто сейчас в эфире (эфирные первыми) |
| `GET /qdl/live/watch/start?camera=` | старт эфира (идемпотентно, общий поток) + статус; клиент опрашивает до `ready` |
| `GET /qdl/live/watch/hls/{camera}/index.m3u8` | живой rolling-плейлист с переписанными сегментными URI (+ ключ периметра) |
| `GET /qdl/live/watch/seg/{camera}/{file}` | сегмент эфира (ts/m4s/init.mp4 — прокси `/hls/{id}/*`) |
| `GET /qdl/live/watch/thumb?camera=` | кадр эфира; фолбек — постер последней записи (mac-рекордеры кадра не имеют) |
| `GET /qdl/live/day?camera=&date=` | статус склейки суток (он же пинок ремуксу): `ready`/`total`/`complete`/`seconds` + путь плейлиста |
| `GET /qdl/live/day/{camera}/{date}/stream.m3u8` | **весь день ОДНОЙ записью** — склеенный HLS (один таймлайн) |
| `GET /qdl/live/seg/{rec}/{file}` | сегмент склейки (прокси `/hls/_vod/...`) |
| `GET /qdl/live/stream?id=` | mp4 одного фрагмента (прокси с Range/seek) — запасной путь |
| `GET /qdl/live/thumb?id=` | кадр-превью записи (прокси) |

## Группы устройств: общая история (`Groups.cs` + `GroupsHistory.cs`, qdl 2.81)
Связанные устройства делят одну историю просмотров. Механика — **подмена айди**: хук
`EventListener.MiddlewareAsync` (`first:false`, то есть после Accsdb и до контроллеров) меняет
`requestInfo.user_uid` с айди устройства на айди группы на путях `/bookmark/*`, `/timecode/*` и
`/reqinfo`. Клиентского кода фича не требует вовсе.

🔴 `/qdl/*` под подмену не попадает **никогда** — права live/rec/manage и реестр устройств
остаются на устройство. `/storage/*` оставлен личным (блоб пишется целиком, общий был бы
единственным местом реальной потери данных).

Реестр — `groups.json` на `cachePath` (рядом с `access.json`), киллсвитч `groupsEnabled: false`.
Управление — вкладка «Группы» в `/admin/d1v`:

| Маршрут | Назначение |
|---|---|
| `GET /admin/d1v/api/groups` | группы + участники + счётчики + список устройств |
| `POST /admin/d1v/api/groups/create\|rename` | завести / переименовать |
| `GET /admin/d1v/api/groups/preview?op=join\|leave\|dissolve` | сухой прогон: что сольётся |
| `POST /admin/d1v/api/groups/join\|leave\|delete` | связать / развязать / расформировать |

Правила слияния и конфликта позиции (в т.ч. «замок обнуления» при одновременном просмотре) —
канон `E:\Media-server\claude\08-clients.md`, разбор — `claude/06` §CP.

## D1versy Live / D1versy Rec — видеорегистратор (`Live.cs`)

**Два раздела в меню**: «D1versy Live» — эфир (живая сетка камер: тайлы с дышащими кадрами,
Enter → эфир фуллскрином), «D1versy Rec» — записи (день одной записью, ниже).

Эфир у регистратора уже есть: `POST /api/streams/{id}/start` поднимает (или находит общий) ffmpeg →
rolling-HLS `/hls/{id}/index.m3u8` (RTSP-камеры — `seg_N.ts`, таргет 2 с; mac-рекордеры — fMP4 с
`EXT-X-MAP init.mp4` + `seg_N.m4s`, их эфир жив только пока приложение на маке пушит). Поток ОБЩИЙ
на всех зрителей и не глушится по бездействию — `stop` не зовём никогда (закрытие плеера у одного
не должно ронять эфир другим). Мы только переписываем живой плейлист на свои сегментные URL
(с ключом периметра на каждой отдаче — живой плейлист не кэшируется вовсе).
Отдельный домашний проект-регистратор (**IPCamLive**, `C:\IPCamLive`: nginx + FastAPI + SQLite) живёт
только в LAN. Модуль его **не меняет и не рестартит** — ходит read-only GET-ами и проксирует наружу
через наш origin, поэтому пункт меню работает и снаружи (периметр D1Vision закрывает пути сам,
нативные плееры подписывают URL через `D1VAuth`), а LAN-адрес регистратора клиенту не виден.

Грабли, зашитые в реализацию:
- Регистратор пишет **наивный UTC** (его контейнер поднят с `TZ=UTC`). Всё, что уходит клиенту,
  переводится в локальную зону, а «локальные сутки» разворачиваются в UTC-окно, которое задевает
  **две** UTC-даты регистратора → его `by-date` спрашивается за обе и режется окном.
- **Основной режим — «весь день одной записью»** (один таймлайн, без «следующего файла»). Склейку
  умеет сам регистратор: каждая запись один раз ремуксится (stream copy, ~9 с на 17 мин видео) в
  TS-сегменты, сшитые через `EXT-X-DISCONTINUITY`. Но его плейлист группирует по **его UTC-суткам**,
  а у нас день локальный (окно задевает две его даты) — поэтому плейлист собираем сами из готовых
  посегментных индексов `/hls/_vod/{rec}/index.m3u8`, ровно по нашему окну. Ремукс запускается
  только его `stitched.m3u8` (внутри `kick_series`) → дёргаем его на каждую задетую UTC-дату; это же
  обновляет TTL-метку кэша, чтобы уборщик (24 ч) не снёс сегменты под зрителем.
- Пока задние куски ремуксятся, плейлист **EVENT** и растёт сам; смотреть можно с первого готового
  куска (замер: холодные сутки из 3 записей — первый кусок через 5 с, все готовы через 14 с).
- Ключ периметра в сегментные строки подставляется **на отдаче**, а не в кэше: кэш общий на всех
  зрителей, а ключ у каждого свой (в LAN его нет).
- Отдельные mp4-фрагменты остались запасным путём (долгое нажатие на камере): записи лежат с `moov`
  в начале (`+faststart` до создания строки в БД), поэтому играются напрямую с Range.

## Конфиг (`init.conf`)
```json
"QbitDownload": {
  "qbitHost": "http://qbittorrent:8080",
  "qbitUser": "admin",
  "qbitPass": "wertykal",
  "downloadsPath": "/downloads",
  "category": "lampa"
}
```
`downloadsPath` — путь, который видят **и** qBittorrent, **и** контейнер Lampac (общий том). В docker-compose: оба монтируют `D:\data\downloads` в `/downloads`.

## Регистрация плагина
В `Modules/LampaWeb/plugins/lampainit-invc.js` (designated-хук) добавлена строка:
`Lampa.Utils.putScriptAsync(["{localhost}/qdl.js"]);`

## Поддержка форка
Вся логика изолирована в этом модуле. Обновление с upstream:
`git fetch upstream && git rebase upstream/main` (конфликт возможен только в `lampainit-invc.js` — одна строка).
