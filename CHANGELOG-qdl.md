# Changelog форка (qdl_fork_version)

Маркер версии живёт в `Modules/LampaWeb/plugins/lampainit-invc.js` (`window.qdl_fork_version`,
виден в консоли клиента). ⚠️ Правило владельца: при КАЖДОМ фиксе клиентских плагинов
(`qdl.js`/`lampainit-invc.js`) бампать минор. До 2.16 полный changelog жил комментарием прямо в
invc и отдавался каждому клиенту (~6.5 КБ на каждый старт) — теперь здесь.

- **2.0** — умная выдача раздач (⭐ скоринг, серии/дата/🔔) + охота за сериями по всем раздачам (`/qdl/episodes`, серии-доноры «врем.», tl-таймлайн) + SWITCH-переключение.
- **2.1** — фиксы ревью: аудио доноров по своему hash, SWITCH-тост без «скачана».
- **2.2** — пункт меню «D1VERSY LIVE»: записи видеорегистратора (день → камеры с записями → плеер, прокси `/qdl/live/*`).
- **2.3** — весь день ОДНОЙ записью с одним таймлайном (склеенный HLS `/qdl/live/day`), фрагменты — запасной путь.
- **2.4** — раздел «D1versy Live» — эфир (живая сетка камер, rolling-HLS `/qdl/live/watch/*`); прежний раздел записей переименован в «D1versy Records».
- **2.5** — «D1versy Records» → «D1versy Rec».
- **2.6** — iPhone: эфир в НАТИВНОМ плеере iOS (прямой click-жест, `<video>` без playsinline, фолбек в VLC, `qdl_ios_live` auto/off); сетка эфира по центру и во всю ширину; видимый фокус пульта в Rec/камере/Уведомлениях.
- **2.7** — фикс iOS-эфира: видимый оверлей вместо скрытого `<video>` (авто-фуллскрин WebKit флакал со второго раза), явный webkitEnterFullscreen, попытки чистят только свой элемент (двойной тап больше не роняет в VLC).
- **2.8** — Rec на пустом «сегодня» сам прыгает на последний день с записями (пустой день на ТВ выглядел как «нет навигации»).
- **2.9** — зеркало прогресса устройства (file_view ↔ нативное KV AndroidJS, ключ `qdl_file_view`) — resume переживает смену хоста LAN↔внешний на iPhone/Mac/Android, браузер не затронут; выкл: `qdl_tl_mirror='off'`, фолбэк «всегда с начала» — `player_timecode='again'`; rawPlay унифицирован на pickTimeline; инварианты слияния: сид-метка t=1, кламп меток из будущего, уважение очистки истории, бюджет посева=кап.
- **2.10** — скорость: прогрев кеша сервера при открытии карточки скачанного (`/qdl/warmup`: голова+хвост файла в page cache + ffprobe-кеш) и прогрев следующей серии при старте плейбека; мемоизация fetchEpisodes (TTL 45 с); сервер: кеш резолва hash+index→путь, кеш ffprobe-дорожек, переиспользование SID-сессии qBittorrent, immutable-кэширование app.min.js/qdl.js/постеров.
- **2.11** — свой ЭКРАН СЕРИЙ (`qdl_episodes`) вместо селектбокса: длинные списки скроллятся на ТВ, «назад» из плеера возвращает в список серий, озвучка помнится и меняется кнопкой; отметки ✓/►N%; общий фикс селектбоксов (upstream-баг mheight — `fixSelectHeight`).
- **2.12** — номер серии бейджем в начале строки экрана серий (`epNumber`) — на iPhone длинные имена обрезались.
- **2.13** — синк с upstream 1.45 + включён модуль Music (флип manifest `enable:true`, клиентам `/music.js`) + свежие yaml-источники NextHUB.
- **2.14** — только НАШИ уведомления: AppPatch режет upstream-колокольчик (иконка Notice + NoticeCub), пункты меню Релизы/Расписание/Подписки, фоновый TimeTable-парсер (TMDB каждые 30 сек) и ряды «Скоро выйдут»/«Недавно вышли»; фиксы дублей qdl-колокольчика/бейджа (dedupe+first, in-flight poll, синглтон `qdl_plugin_loaded`, агрегация тостов); CSS-фолбэк на случай смены tree; `disable_features.subscribe=true`.
- **2.15** — локализация внешних источников (карта — Media-server `claude/11`): клиент ходит ТОЛЬКО на наш сервер (исключения: YouTube-трейлеры, стрим балансеров) — форс `proxy_tmdb=true` каждую загрузку (LAN-клиенты по GeoIP получали false и ходили на TMDB напрямую), `lampa_settings.mirrors=false` (проба зеркал CUB), `lampa_settings.geo=false`, watch-пинг `$.get('tmdb.<cub>/watch?id=')` → локальная заглушка `/cub/api/checker` (XHR-патч); сервер: MyLocalIp-хук вместо api.ipify.org, прогрев каталога CatalogWarmup, вендор плагинов магазина расширений (`/ext/*`).
- **2.16** — скорость (боевой лог — Media-server `claude/06` §AS): precompressed brotli-q9 в Staticache (жмём один раз, HIT отдаёт готовый .br), `music.js`/`lampainit.js` → immutable при ?v, Cache-Control всей статике (vender/fonts/lang/ext), постеры `/tmdb/img` — immutable-год, AppCacheVersion без ticks процесса (рестарт не сбрасывает клиентские кеши), CatalogWarmup v2 (парс рядов → прогрев постеров и деталей карточек), preload бандла + динамический ?v CSS + jquery/scrollbar min в вендоре index.html, быстрый вотчер Lampa (25 мс вместо 200) с идемпотентным appload, changelog вынесен сюда (−6.5 КБ с каждого старта).
- **2.17** — витрина расширений CUB локально (Media-server `claude/06` §AT): темы, скринсейверы и премиум-контент отдаются со своего сервера. Выяснилось, что не работала НИ ОДНА тема/скринсейвер — cub отвечает 302 на cdn.cub.bz, а CubProxy редиректы не тянул; премиум сверх того гейтился токеном. Всё содержимое (3 темы CSS, 18 скринсейверов MP4, 28 плагинов витрины, превью) вендорится `scripts/vendor-cub-extensions.ps1` в `lampa-vendor/cub-ext`; ручки `CubExtensions.cs` отдают `/cub/red/api/extensions/list` (локальный каталог, premium=0 у всего) и `/cub/red/extensions/<id>` (CSS/MP4 с Range и immutable-кешем), при отсутствии копии — редирект на upstream + запись в лог.
- **2.18** — данные устройства на СЕРВЕРЕ (per-device): включён upstream-комплект `Modules/Sync` (TimeCode — прогресс, Bookmark — закладки/история/избранное, Storage — KV, SyncEvents — realtime WS; init.conf: SkipModules минус Sync/TimeCode, `initPlugins.sync=true`, `Sync.fullset=true`); сеятель стабильного uid устройства в lampainit-invc (канон в нативном KV `qdl_device_uid`, пересев в `lampac_unic_id` каждого origin — LAN и tv.d1versy.com теперь ОДНО устройство); наш дифф в `Sync/TimeCode/plugin.js`: card_id-переопределение `window.qdl_timecode_card` (иначе экраны без карточки падали в ведро 0_movie), анти-клоббер `Timeline.read()` в том же тике, событие `timecode_updated`; qdl.js: зеркало `qdl_file_view` → аварийный фолбэк (режим 'auto': сервер появился — зеркало не стартует, 15 с таймаут — старое поведение; 'on' форс / 'off'), экран серий ставит бакет таймкодов (seriesKey из f.tl) + pull с сервера + перерисовка бейджей. Параллельно Android-клиент 568: встроенный libVLC-плеер (паритет mac/iOS), внешние плееры отключены.
- **2.19** — скорость + добивание изоляции + диагностика охоты (боевой лог — Media-server `claude/06` §AV): `CleanupHls` убран из отдачи `playlist.m3u8` — обход 4407 файлов кеша через 9p стоил 2.6–3.4 с НА КАЖДЫЙ запрос плейлиста, чистка переехала в `_hlsIdleTimer` с троттлом раз в 60 с (TTFB плейлиста 8–24 мс); `Cache-Control` в экшене Hls (сегменты immutable-год, плейлисты no-cache — не было ничего); TTL Staticache для ?v-адресуемой статики 20 мин → 7 суток; прогрев деталей греет КЛИЕНТСКУЮ форму `/tmdb/api/3/…` (грелся `/cub/tmdb./3/…` — другой ключ кеша, работа уходила в никуда) + прогрев фона карточки w1280; `/tmdb/api` подставляет серверный ключ (`tmdb.api_key`, фолбэк `cub.api_key`), `api_key` исключён из ключа кеша, не-2xx больше не кешируется. Изоляция: `socket_use`/`socket_methods=false` (WebSocket на cub.rip был единственной ПОСТОЯННО активной утечкой), `screensaver=false` + тип `cub` (по умолчанию был `aerial` — raw.githubusercontent.com и чужой CDN через 5 минут простоя), `services=false`, ранний return из `Preroll.show` (Google IMA SDK не грузится — маркеров `qdl-cut` стало 7), DMCA-запрос строится локальным URL, `/d1vision/hosts.json` отдаёт только `*.d1versy.com` и приватные IP. Охота: топ-N кандидатов за проход (ручка `donorProbesPerRun` была мёртвой), пустая выдача индексатора не засчитывается как проход, логи отсева (раньше охота была бесшумной), догон по `hunt.lastRun` (писался, но не читался), уведомление `kind=START` + мгновенный пуш по `/nws`. Tizen: убран безусловный YouTube iframe_api по открытому HTTP. Healthcheck lampac: HTTP-проба Kestrel вместо `pgrep` (живой процесс ≠ живой сервер).
- **2.20** — грид «Загрузок» раскладывается как штатный каталог (боевой лог — Media-server `claude/06` §AV п.9): карточки были прижаты влево, справа 100 px пустоты на 1280. Причина — класс контейнера, а не наш CSS: штатный каталог кладёт карточки в `.mapping--grid.cols--6`, где правило `.cols--N > *` задаёт долю 100/N %, а `ComponentDownloads` строил DOM руками с legacy-`.category-full`, где `.card` остаётся при своей фиксированной `width:12.75em`. ⚠️ Медиазапросы `.cols--6` приезжают в комплекте (на 480 px раскладка сама 4-колоночная), но правило растягивает ЛЮБОГО прямого потомка — сообщениям о пустом списке понадобился явный `width:100%`. Тест версии плагина перестал пинить литерал (сравнивает номер) — иначе падал бы на каждом бампе минора.
- **2.21** — платформа **windows** (нативный клиент D1Vision для Windows; устройство — Media-server `claude/12`, грабли — `claude/06` §AW): UA-токен `d1vision_windows` в регексе платформ `lampainit-invc.js` + ветка андроидных форс-ключей (у клиента есть нативный мост AndroidJS, «замки» 2 и 3); MIME `.exe`/`.msi`/`.nupkg` в `Controller.cs` — OTA-раздача Velopack (роут `/d1vision/apps/{platform}/{**file}` уже был универсален). Ключ периметра `d1v.keys.windows` заведён в `init.conf` (вне git, hot-reload) — правок `D1VPerimeter` не потребовалось: `IsValidKey` перебирает все `keys.Values`.
- **2.22** — постеры «Загрузок» скачиваются снова (боевой лог — Media-server `claude/06` §AX). Побочка 2.15: форс `proxy_tmdb=true` сменил то, что возвращает `Lampa.TMDB.image`, и клиент стал слать в `poster_url` НАШ прокси (`http://192.168.87.24:9118/tmdb/img/…`) вместо `image.tmdb.org` — анти-SSRF гард `/qdl/save` («https И не приватный хост») резал это МОЛЧА, у всех новых загрузок `has_poster=false` и серая заглушка в гриде; `healPoster` строил тот же URL и вылечить не мог. Внешний путь был сломан ещё раньше (нет hairpin-NAT из контейнера). Фикс серверный, клиент не меняется: `TmdbPosterPath` достаёт из `poster_url` относительный путь TMDB (или берёт `poster_path` из меты на диске — ветка для `healPoster`, который шлёт запрос без `card`), белый список пути режет traversal; качаем через свой `/tmdb/img` на loopback с подменой Host/X-Forwarded-Proto на клиентские (ключ Staticache = Scheme+Host+Path — иначе греется чужой бакет), фолбэк на прямой TMDB. Плюс антистампед по хэшу и лог с троттлом вместо молчаливого пропуска — именно молчание скрыло поломку на сутки.
